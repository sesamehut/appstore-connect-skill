# 产品范围：App Store Connect 自动化

本文定义本 skill 的产品定位与边界。

**定位**：面向不写代码的用户（产品经理、设计与艺术工作者），用自然语言驱动 Apple 应用发布全流程——把 `App-Store-Connect-CLI` 这类通用 CLI 的能力广度，交给碰不了命令行的人。能力面分三条线：ASC REST API、Apple 广告 API、本地 Apple 工具链。

数据采集时间：**2026-06**。实现前应按 Apple 官方文档和 OpenAPI spec 复核。

## 问题背景

App Store Connect 覆盖发布、测试、销售、报表、评论和账号管理等多个工作面。网页端可以完成大多数操作，但很多重复性任务适合自动化，例如批量读取元数据、准备送审材料、下载报表、整理评论和维护测试人员。

公开 REST API 覆盖面很广，但不是网页端的完整镜像。部分合同、财务、法务和审核沟通能力仍只能在网页端处理。因此，本 skill 需要从一开始就把“可自动化能力”和“必须人工网页端处理的能力”分清楚。

通用 CLI 已经把这些能力覆盖得很全，但面向程序员，把不写代码的人挡在门外。本 skill 用自然语言承接同样的广度，能力面因此不止 ASC REST API，还包括 Apple 广告和在用户机器上编排的本地工具链（构建、公证、签名、二进制上传）；需把“可经 REST API 自动化”“需本地工具链执行”“必须网页端处理”三类分清。

## 产品目标

- 让不写代码的用户用自然语言完成 Apple 应用发布全流程，无需接触命令行或 API。
- 能力广度对齐通用 CLI（发布/元数据/TestFlight/报表/评论、商业化/营销、广告、本地构建/公证/签名），以自然语言可达性超越。
- 对 API 不支持、权限不足、账号条件不满足、或需本地工具链的场景，给出人话反馈与下一步。
- 三类能力分清，不把“需本地执行”“须网页端处理”误包装成普通 REST 能力。

## 能力分组

| 分组 | 产品判断 |
|---|---|
| 应用与版本管理 | 作为核心能力，覆盖元数据、本地化、版本状态和送审准备 |
| TestFlight | 作为核心能力，覆盖测试分发、测试员和反馈读取 |
| 商业化资源 | 作为扩展能力，覆盖内购、订阅、价格、优惠和地区可用性 |
| 营销资源 | 作为扩展能力，覆盖自定义产品页、应用内事件和产品页实验 |
| 媒体素材 | 作为核心工作流，单独处理截图和预览素材上传 |
| 报表与分析 | 作为核心工作流，单独处理下载、解析和权限提示 |
| 评分与评论 | 作为核心能力，覆盖读取和开发者回复 |
| 组织与访问 | 作为受限能力，覆盖公开 API 支持的用户和角色管理 |
| Provisioning | 作为受限能力，覆盖公开 API 支持的证书、标识和配置材料 |
| Xcode Cloud 与 Webhooks | 作为后续集成能力，根据具体需求推进 |
| EU 替代分发 | 作为条件能力，依赖账号资格和业务条款 |
| Apple 广告（Apple Search Ads） | 作为扩展能力，独立于 ASC 的另一条认证与契约线 |
| 本地 Apple 工具链 | 作为代理能力，在用户机器上编排构建、公证、签名与 build 二进制上传，需显式确认 |

最后两行跨出 ASC REST API（广告是另一套 Apple API，本地工具链在用户机器上执行命令），按 [Roadmap](../phases/roadmap.md) M9+ 推进，落地前在 [架构总览](../architecture/overview.md) 确认信任边界。

## 首期建议范围

首期优先覆盖工程价值高、边界清晰、容易验证的能力：

- 应用、版本、元数据和本地化管理。
- 截图和预览素材工作流。
- 送审准备与发布配置。
- TestFlight 基础管理。
- 销售、财务和分析报表工作流。
- 评论读取与开发者回复。

暂缓实现：

- Webhooks 接收端。
- 产品页实验结果分析。

更广的能力（商业化、营销、广告、本地工具链含 build 二进制上传、Xcode Cloud、EU 替代分发）按 [Roadmap](../phases/roadmap.md) M9+ 分批推进。

## 明确不支持

以下能力 Apple 公开 API 与工具链根本无法触达（Apple 的硬限制，非本项目取舍）。本 skill 的职责是讲清前置条件、引导用户去网页端完成：

- 协议、税务、银行和收款账户管理。
- 审核沟通中心中的往来消息。
- 创建或下载新的 ASC API key。
- 依赖网页端内部接口的能力。
- 需要网页会话而不是 ASC API key 的能力。

## 设计要求

- 面向不写代码的用户：用人话输出，不暴露命令/flag/HTTP 细节；错误与前置条件给出可执行的下一步。
- 凭证上手（ASC API key 与 .p8）是非程序员最大门槛，需重点引导。
- 本地工具链执行是特权动作：运行前显式确认并展示确切命令，检测环境（macOS + Xcode）、缺失时优雅降级。
- Skill 输出应区分“Apple API 不支持”和“本项目暂未实现”。
- 需要网页端完成的动作，应给出明确前置条件或人工处理说明。
- 多步骤文件流程应作为任务流程呈现，而不是伪装成普通资源请求。
- 权限不足时，应提示权限问题和可能需要的角色范围。
